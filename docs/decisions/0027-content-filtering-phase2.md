## 2. 决策（owner 2026-09-20 拍板，引 #740）

拍板原文（逐字）：

> **本地规则 + shadow + 异步 + 不阻断**。
> **shadow 只产出规则命中计数 / 类别 / 延迟等非正文观测；不因为 shadow 就扩大 retention scope**（禁止"为了调查命中而顺手把正文/code/tool payload 写进审计"）。

展开为可检查的句子：

- **D1 本地规则**：命中判定由本地规则完成（在网关进程内执行），**不引入外部审核服务**、不新增任何正文离开网关的数据通道。可检查：实现轮不得新增外部内容审核服务客户端；正文只在网关进程内被读取用于本地匹配。
- **D2 shadow**：命中只观察、只产出观测——**不对请求或响应做任何动作**（不拒绝、不改写、不截断、不注入）。可检查：任何请求/响应字节不因内容过滤而变化。
- **D3 异步**：观测产出的上报走异步路径、**不阻塞请求热路径**（对齐 §3.3 引述的「热路径只加计数器」原则）。
- **D4 不阻断**：本决策形态下**业务误杀面为零**——没有任何请求会因内容命中被拦、被改或被降级；「拦截」能力不在本决策内（未来若做，另行拍板）。
- **D5 shadow 观测边界**：观测**只含非正文数据**——规则命中计数 / 类别 / 延迟等；**不因为 shadow 就扩大 retention scope**——禁止为调查命中把正文 / 代码 / tool payload 写进审计（`RetentionEnvelope` 不扩字段、ADR-0014 的采集范围与开关不动，详见 §3.4）。
- **D6 默认关闭**：该能力默认关闭，**开启需管理员显式配置**。opt-in 风格延续既有先例：ADR-0014「P2 默认状态：**默认关闭**（对齐主流"最小留存"），部署配置开启（`MIQROKEY_RETENTION_*`）」（`docs/decisions/0014-content-retention-and-kafka-events.md:150`；同义表述 `:83`「留痕为**独立、默认关闭**的可配置通道」）；ADR-0020「存量规则、默认模板复制出的规则、未携带该字段的旧客户端一律保持 `ALERT`——**默认行为与今天完全一致**」（`docs/decisions/0020-quota-soft-landing.md:46-48`）；实现侧坐标 = 租户开关默认全关、无行即零采集（`docs/api-contract.md:1181-1183`、`RetentionConfig.java:5-8`）。

## 3. #740 验收四问逐一作答

### 3.1 合规边界：「拦截 = 碰正文」与「正文不出网关」

- 内容过滤若做**拦截**，必须读取正文做判定——属「碰正文」动作。本决策形态是**本地规则、进程内执行、不引外部审核服务、且不阻断**：正文只在网关进程内被本地规则读取匹配，**不出网关**（不落盘、不出进程；观测里只有计数/类别/延迟等非正文数据）。
- 因此与既有「正文不出网关」原则**相容**（原则表述见 `docs/decisions/0022-semantic-cache-evaluation.md:25`；落盘红线见 `CLAUDE.md:39`，唯一例外通道 = ADR-0014 密文留痕，本决策不触碰、不放宽）。
- **明文边界（不得援引本 ADR 绕过）**：**未来若接入外部审核服务（如腾讯天御 TMS 一类）＝ 正文出网关，必须另开 ADR 明确授权——不得援引本 ADR 作为依据。** 先例即 ADR-0022 的结论：不能把 ADR-0014 当作「正文出网关已获授权」的通例——0014 的授权是针对密文信封这一具体形态给出的三个放宽点（`docs/decisions/0022-semantic-cache-evaluation.md:55`）。

### 3.2 审核服务选型

- **不选型**——本形态（本地规则）下 N/A：无服务账号、无配额、无按次计费项。
- 外部审核服务的评估列为**条件项**，触发条件写入 §5（重新评估条件）：出现必须「出网审核」的合规要求；或外部审核服务进入采购范围。触发时按 §3.1 的明文边界另开 ADR，先做数据出域与协议评估。

### 3.3 误杀与延迟

- **误杀**：shadow 观察先行 → **不阻断**，两者叠加 ⇒ **业务误杀面为零**（没有任何请求因命中被拦/改；观测本身不影响响应）。误杀率的评估是未来「是否上阻断」的前置条件（§5 条件 1）。
- **延迟**：观测路径**不得阻塞热路径**——对齐网关既有「热路径只加计数器」原则。坐标：`docs/platform-event-model.md:25`（引 `PostgresUsageEventBus.java:133-144` 的 `offer()` 只自增内存计数、从不调度工作、从不碰 JDBC；同文件 `:55-62` 的注释把这条设计写死）、`:72`（普适规矩：热路径只加计数器；上报由独立周期任务做；写失败必须可归还、可重试）。因此：**对业务请求的延迟影响 = 零**（不阻断、观测异步）；**观测路径自身的延迟预算数字属实现轮**（列入 §7 未决项）。

### 3.4 与留痕管道的关系

- **#588 的 Phase 2 审核字段（score / suggestion / label）不因此开启**——#588 维持 Phase 1 冻结：本决策不触碰留痕管道的既有字段与开关，`RetentionEnvelope` 不新增字段（现状 13 字段中无任何审核字段，`RetentionEnvelope.java:12-14`）。
- shadow 观测的出口是**指标 / 日志（非正文）**：不进 `RetentionEnvelope`、**不扩 retention scope**——不因 shadow 把正文 / 代码 / tool payload 写进审计。ADR-0014 的边界与放宽点原样（`docs/decisions/0014-content-retention-and-kafka-events.md:81-86` 的三个放宽点、`:150` 的默认关闭、`:187-199` 的双面增补均不变）。
- 可援引的既有实现先例：ADR-0024 选项 B / #770「只观测」——有界只读分类、只产枚举类别计数与一行日志，正文不进日志、不落库、不进事件（`docs/security.md:76`）。

## 4. 被否的替代方案

| 方案 | 否决理由 |
|---|---|
| A. 直接上同步拦截（无 shadow 观察期） | 无实测数据前阻断 = 用未校准规则误杀正常流量；拦截判定若串在首包前，直接冲突首包 P95 ≤ 30ms 红线（`docs/product-requirements.md:128`）；输出侧阻断（截断/注入错误事件）改变响应语义，超出现有 ADR 依据（#740 决策材料 §2/§5）。 |
| B. 同步送审外部审核服务（腾讯天御 TMS 或等价） | **正文出网关** = 新数据通道，须独立 ADR 授权（§3.1）；账号/配额/计费属采购项；外部 RTT 若串在首包前，30ms 预算大概率需重估（#740 决策材料 §3）。 |
| C. 把命中信息写进留痕信封 / 审计（复用 #588 Phase 2 字段） | 直接违反 shadow 边界（不因 shadow 扩大 retention scope，D5/§3.4）；信封扩字段需评估兼容与授权；观测口径不应依赖「留存正文」通道——观测出口 = 指标/日志（非正文）。 |
| D. 完全不做（维持现状） | 未采纳：PPT 路线图 P22/P24 的该项承诺与 #740 的 tracking 目的不收口；owner 拍板取 shadow 方向。 |

## 5. 重新评估条件（可判定；满足任一即重新评估）

满足任一条件 → 对「是否上阻断 / 是否接入外部审核服务」重新评估。**重新评估 ≠ 自动开启**：任何开启仍须 owner 拍板；涉及正文出网关的形态必须先另开 ADR（§3.1）。

1. **shadow 数据积累到足以评估误杀率**：shadow 观测已上线运行，且积累的命中计数 / 类别 / 延迟数据达到可支撑误杀率评估的规模（判定方式 = 以观测数据为证据、由 owner 裁定门槛；本 ADR 不预设数字）。
2. **出现必须「出网审核」的合规要求**：对外承诺 / 客户合同 / 监管要求明确要求使用外部内容审核服务（以书面要求出现即判命中）→ 按 §3.1 另开 ADR（正文出网关的授权与数据出域评估）。
3. **外部审核服务进入采购范围**：腾讯天御 TMS 或等价服务的账号 / 配额 / 预算进入正式采购流程（采购立项发生即判命中）→ 先做 §3.2 的条件项评估，再按 §3.1 另开 ADR。

## 6. 后果

- **业务面**：零行为变化——shadow 不阻断（D4）；默认关闭时连观测也不发生（D6），与今天完全一致。
- **数据面**：观测产物 = 命中计数 / 类别 / 延迟（非正文）→ 指标与日志；不进 `RetentionEnvelope`、不扩 retention scope（D5、§3.4）。
- **热路径**：观测产出异步、只加计数器口径（D3、§3.3）；业务请求延迟影响为零。
- **合规面**：正文不出网关维持不变（§3.1）；无新数据通道；ADR-0014 的边界、开关、字段全部原样。
- **成本面**：本地规则不引入账号 / 配额 / 按次计费项；成本主要在开发与规则集 / 词表的持续维护（实现轮范畴）。
- **风险与缓解**：
  - *本地规则召回有限*（相对云端审核能力）：shadow 阶段零业务代价；观测数据本身即后续决策依据（§5 条件 1）。
  - *对外误读*：本能力容易被误表述为「已拦截 / 已送审」——对外表述必须以本 ADR 为准：观测、默认关、不阻断；拦截未启用。
  - *观测通道静默失效*：若无自观测，「无命中」与「观测没在跑」不可区分——实现轮需给出可区分的观测形态（形态未决，见 §7）。
