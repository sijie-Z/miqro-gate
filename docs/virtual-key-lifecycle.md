# Virtual Key 生命周期

## 1. 创建前提

普通用户只有在同时满足以下条件时才能创建 Virtual Key：

- 账号处于 ACTIVE；
- 是目标项目成员；
- 项目存在 ACTIVE 的 ProjectProviderGrant；
- Grant 绑定的真实凭证处于 ACTIVE；
- 至少有一个已授权模型。

## 2. 创建流程

用户选择：

- 项目；
- 供应商产品；
- 管理员已绑定的凭证授权项；
- 用途标签；
- Key 名称；
- 在项目授权范围内的一组模型。

后端生成至少 256 bit 随机 secret，返回完整 Key 一次。数据库保存：

- 可公开的 `public_key_id`；
- 使用服务端 pepper 计算的 HMAC-SHA-256 摘要；
- 可展示前缀和末四位；
- 归属与授权快照。

创建响应明确提示“关闭后无法再次查看”。

## 3. 使用

Gateway 从 Key 中解析 `public_key_id`，读取记录后以常量时间比较 secret 摘要。验证通过后使用 Key 的固定路由，不根据模型、负载或错误选择其他真实凭证。

Key 默认永不过期。系统记录 `last_used_at`，可以对长期未使用 Key 发送清理提醒，但不自动禁用。

## 4. 轮换

用户可以轮换自己的 Key，管理员也可以代为轮换。建议流程：

1. 生成新 Key 并一次性显示。
2. 旧 Key 进入 `ROTATING`。
3. 默认立即吊销旧 Key；实现可保留一个由管理员配置的短暂过渡期。
4. 新旧关系写入审计。

首版默认立即吊销，减少同时有效 Key 数量；如客户实际切换 CC Switch 需要过渡期，再启用可配置窗口。

## 5. 吊销与禁用

- 用户可以吊销自己的 Key，操作不可撤销。
- 管理员可以禁用或吊销任意 Key。
- 禁用保留恢复可能；吊销不可恢复。
- 项目成员移除、Grant 停用或真实凭证停用时，关联 Virtual Key 即时不可用。

## 6. 真实凭证轮换

真实凭证轮换不改变 Virtual Key：

1. 管理员在同一个 UpstreamCredential 槽位提交新 Secret。
2. 系统加密保存为新版本，并调用 CredentialValidator。
3. 验证成功后发布新路由快照。
4. 新请求使用新版本；旧版本仅等待在途请求结束。
5. 旧密文标记 retired，并按安全保留期清理。

验证失败时不得覆盖当前有效版本。

## 7. Base URL 与展示

普通用户 Key 详情页展示：

- Key 名称、前缀、末四位；
- Base URL；
- 项目、供应商产品和用途；
- 可用模型；
- 创建、最后使用时间和状态；
- 个人用量快捷入口。

不展示真实凭证标识、Plan 总余额或其他人的数据。

## 8. 审计事件

至少记录：创建、复制页面首次展示确认、轮换、吊销、管理员禁用、授权变化导致失效、真实凭证版本切换。审计日志绝不包含完整 Virtual Key 或真实 Key。
