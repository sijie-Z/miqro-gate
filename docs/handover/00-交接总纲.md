### Spring Boot 4 升级：已完成

| 阶段 | 状态 |
|---|---|
| **Stage A**：Boot 3.5.16 → 4.1.1、springdoc 2.8.9 → 3.1.1 | ✅ 已合并（PR #1170 / `eaaf3f9`） |
| **Stage B**：Jackson 2 → Jackson 3 全量迁移 | ✅ **已完成**。批次 1–5b（#1172 / #1189 / #1192 / #1195 / #1210 / #1214）+ **收尾批**（`5d4c3bca`：摘除 `spring-boot-jackson2` 过渡模块与全部 `preferred-json-mapper` 接线）<br>现状：全仓 `tools.jackson` **206 个文件**，`com.fasterxml` 只剩 **2 个**（合法的 `jackson-annotations`） |

> ✅ **曾经有一堵"安全承重墙"，现在已经拆了——但要知道它的来龙去脉**：
> 过渡期里 `UserMixin`（排除 `passwordHash`）挂在 **Jackson 2** 定制器上（`Jackson2ObjectMapperBuilderCustomizer` + `builder.mixIn(...)`），而 Boot 4 的 HTTP 层默认走 Jackson 3。所以那时**必须**钉住 `preferred-json-mapper: jackson2`，删了就会泄漏密码哈希。
>
> **收尾批（`5d4c3bca`）已把它整体搬到 Jackson 3**：`JacksonConfig.java` 现在用 `org.springframework.boot.jackson.autoconfigure.JsonMapperBuilderCustomizer` 的 **`builder.addMixIn(User.class, UserMixin.class)`**；两个 `application.yml` 里的 `preferred-json-mapper` 与 pom 里的 `spring-boot-jackson2` 一并摘除。**保护没有减弱，只是搬了家。**
>
> ⚠️ **以后要改 `JacksonConfig` 时**：`UserMixin` 是唯一的保护点。改完务必确认 `/auth/login`、`/me`、用户列表的响应里**不出现 `passwordHash`**。
>
> ⚠️ **最隐蔽的坑**：`spring.autoconfigure.exclude` 里的**类名字符串在 Boot 4 会静默失效**，会导致一次性 53 个测试类报错——**编译器查不出来**。

### 明确不做（红线，改前必须新开 ADR + owner 同意）

- **不做跨协议转换**——网关是透明代理，协议转换和模型映射由 **CC Switch** 负责（ADR-0002）
- **不是**智能路由平台 / 模型聚合中转站
- 不自动故障切换；首字节前最多安全重试一次，流开始后不重试
- **不保存 prompt、代码、工具正文和模型回答**（唯一例外：ADR-0014 允许默认关闭的密文留痕通道）
- 第一版不做模型响应缓存、不部署 Redis（**ADR-0009 已推翻"不做缓存"**，见下）

### 7.3 数据面关键事实（接手必知）

- **网关没有 Spring Security filter chain、没有 `HandlerInterceptor`、没有 `@ControllerAdvice`、没有 `ErrorWebExceptionHandler`**
  → 所有鉴权 / 限流 / 错误信封**都在 controller 方法体里手写**。改鉴权 = 改 `ProxyController`，不是加 filter
- **四条铁律**（代码里反复强调）：
  1. 热路径绝不阻塞（JDBC/文件/DNS 都切到 `credentialDecryptScheduler`）
  2. 热路径不查数据库（路由/凭证/密钥/模型授权全来自内存快照 `RouteSnapshot`）
  3. 请求体**字节级透传**，网关从不重新序列化
  4. **指标零标签**（不允许 user/key/model/vendor 进 metric tag）
- 模块依赖方向由 **ArchUnit 钉死**（`ModuleDependencyTest.java`），违反直接测试失败

### 7.4 前端关键事实

- **没有全局 401 拦截器**——唯一的 401 判定在 `stores/auth.ts`；其余错误逐页面自理
- `gen:types` 产出的是 `src/types/generated.ts`，**不是** `generated-api.ts`（后者是手写别名层）
- `views/next/` 的 "next" 是**已退役的历史命名**（`/app-new/*` 现在只做 redirect）
- 主色文档写 `#1677ff`，实际是 `#0960bd`
- `PageHeader.vue` + 部分 `global.css` 是死代码
