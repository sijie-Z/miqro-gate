## 1. 这系统解决什么问题

### 1.1 一组真实场景

**场景 A：一把真实 Key 要分给五个人。**
团队买了 DeepSeek 的按量 API，只有一把 `sk-…`。直接发给五个同事，会发生什么：

- 有人在群里转发了它，你不知道；
- 月底账单来了，只有一行总额，**你不知道这 800 块是哪个项目烧的**；
- 想收回来，得挨个通知五个人改配置——而你可能根本不知道第五个人是谁；
- Key 泄漏了，唯一动作是「去官网作废重发」，五个人同时中断。

**场景 B：换 Key 要改一圈客户端配置。**
供应商给了新 Key。每个人本机的 Claude Code、Codex、IDE 插件、脚本里都存着旧的 —— 挨个改。

**场景 C：套餐型产品根本没法按量记账。**
GLM 团队版是按席位的、腾讯企业版是多 Key 共享池的。这些产品的「用了多少」不是一行 token 数，
而是「哪个席位、哪个池子、这个周期还剩多少」。

**场景 D：出事了要查。**
有人用公司额度跑了私活，或者拿模型生成了不该生成的内容。你需要能回答「**谁、什么时候、用了哪个模型**」——
但你可能**不该**保存所有人跟模型的完整对话。

### 1.2 MiQroGate 的答案

```text
员工工具/应用 ──(虚拟密钥 mqk_live_… + 网关地址)──▶ MiQroGate ──▶ 真实供应商（DeepSeek/通义/Kimi/GLM/…）
                                                        │
                                                        └─▶ 用量事件 / 审计链 / 配额水位 / 成本账本
```

一句话：**把真实凭证收进保险库，把「谁在用」变成一把可追溯、可吊销、可归属的虚拟密钥。**

对应上面四个场景：

| 场景 | 方案 | 在本系统的形态 |
|---|---|---|
| A 共享 Key | 一人一把虚拟密钥，真实 Key 只存网关 | 「我的密钥」自助创建，`me/virtual-keys` |
| A 归属不明 | 每笔请求归属到 用户 × 项目 | `key_project_binding` + Grant |
| B 换 Key | 真实凭证后台轮换，虚拟密钥与 Base URL 不变 | 凭证「轮换」→ 快照秒级刷新 |
| C 套餐形态 | 用 `billing_mode` / `credential_topology` / `quota_topology` 描述产品 | `ProviderProduct` 领域模型 |
| D 可查 | 默认只记元数据；正文留痕是**显式开启**的独立能力 | 审计链 + ADR-0014 留痕（默认关） |

> **定位**：这是**企业内部的 AI 凭证虚拟化 + 用量治理网关**。对使用者是「换个地址、换把钥匙」的透明代理；
> 对管理员是「谁花了多少、什么时候该刹车」的账本与闸门。
> 它**不**是模型路由平台，**不**是协议转换层，**也 不**是内容审核系统（见 §7）。

## 2. 谁在用：角色与权限

### 2.1 代码里只有两种角色（重要）

`backend/domain/src/main/java/com/miqroera/miqrokey/domain/model/UserRole.java:5`：

```java
public enum UserRole { SYSTEM_ADMIN, USER }
```

**「项目管理员」这个角色不存在。** 全仓 `grep -ri "PROJECT_ADMIN|projectAdmin|项目管理员"` **零命中**；
`docs/domain-model.md:68` 也写明「首版没有项目管理员，成员关系只能由系统管理员修改」。
项目、授权、成员关系全部是 `SYSTEM_ADMIN` 独占的动作——接手的第一个认知校准点。

### 2.2 四种「使用者」的实际边界

| 身份 | 代码里的表示 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **普通开发者**（`USER`） | `UserRole.USER` | 自助注册/登录；在自己参加的项目内**免审批**建虚拟密钥；轮换/停用/吊销自己的 Key；看**自己**的用量；提交模型申请；下载被授权的技能包 | 看不了别人的数据、真实 Key、项目总量、管理员审计；改不了授权边界 |
| **系统管理员**（`SYSTEM_ADMIN`） | `UserRole.SYSTEM_ADMIN` | 全部。用户/团队/项目/授权/审批、供应商产品/订阅/凭证、配额、成本/对账/定价、审计、告警、MCP、Agent、开放 API 密钥 | —— |
| **机器调用方（外部系统）** | `api_consumers` 行 | 用 `mqk_api_…` 或自签 RS256 JWT 调 `/api/v1/billing/**`（需 `billing:read`）与 MCP 数据面 `/mcpservers/**`（需 `mcp:call`） | 能力**默认全拒**，必须显式勾选；进不了管理面 |
| **机器调用方（运维自动化）** | `admin_api_keys` 行 | 用 `mqk_admin_…` 调开放管理 API `/api/v1/admin-api/**`（用量/审计/Key/配额/导出/MCP 日志读面 + 告警规则与 Webhook 全生命周期 + 导出任务创建 + 代建虚拟密钥） | 需要在管理面显式签发密钥；写操作受 ADR-0016 的执行者语义约束 |

### 2.3 权限是怎么落地的

- **后端是 deny-by-default**：`RoleInterceptor` 对 `/api/v1/admin/**` 一律要求 `SYSTEM_ADMIN`，
  非管理员返回 403 `FORBIDDEN`——见 `backend/control-plane-app/src/main/java/com/miqroera/miqrokey/controlplane/security/RoleInterceptor.java:38,44`。
  注意：**前端导航的隐藏不是安全边界**，真正的门在这层。
- **前端只是体验**：`frontend/src/router/index.ts:310` —— `requiresAdmin` 的路由对非管理员**重定向到「我的密钥」**
  （而不是渲染一个 403 页）。
- **注册默认开**：`backend/control-plane-app/src/main/resources/application.yml:31`
  `registration-enabled: ${MIQROKEY_REGISTRATION_ENABLED:true}`。
  即部署出来默认是「自助注册」，不是「管理员手工建号」。管理员建号路径仍然可用
  （一次性临时密码 + 首登强制改密，`AdminUserController`）。
- **平台单点登录**：ADR-0017 的 OIDC 授权码流程已接，`miqrokey.platform-oidc-auto-provision` 默认 `true`（首登自动建 `USER`）。
  用户身份映射表 `user_identity_link` 同时服务于留痕管道（ADR-0014 R4）。

### 2.4 团队 vs 项目（别搞混）

| 实体 | 角色 | 一句话 |
|---|---|---|
| **团队 Team** | 纯组织标签，N:M，可一人多团队 | **不承担授权，也不归集成本**（`docs/domain-model.md:46`） |
| **项目 Project** | **权限与成本的载体** | 授权、虚拟密钥、用量归属、配额作用域都挂在项目上 |

## 3. 核心概念

每个概念一句话说清「是什么、为什么要它」。

### 3.1 凭证与密钥

| 概念 | 是什么 | 为什么要它 |
|---|---|---|
| **虚拟密钥 Virtual Key** | 用户手里的凭据，形如 `mqk_live_<publicKeyId>_<secret>`，可带 `.项目标签` 后缀。库里只存 HMAC-SHA-256 摘要，明文**只在创建/轮换时显示一次** | 让真实 Key 不出保险库；一人一把、可单独吊销 |
| **上游凭证 UpstreamCredential** | 供应商官网申请的真实 Key（如 `sk-…`），加密保存、门户永不回显 | 唯一需要保密的资产；轮换它就是轮换了一切 |
| **供应商产品 ProviderProduct** | 某个供应商下一个有**明确协议/鉴权/计费规则**的产品实例（如 `deepseek-payg-api`、`tencent-coding-plan`） | 光有「DeepSeek」不够——按量 API 和 Coding Plan 的鉴权与计量完全不同 |
| **订阅 UpstreamSubscription** | 一次实际购买/开通的套餐或账户资源；按量 API 也可用无周期订阅表示余额容器 | 承载周期、总量、席位、余额来源 |
| **席位 PlanSeat** | 团队/企业套餐里的一个座位（可绑人，也可只当额度格） | 腾讯企业版是多 Key 共享池、智谱/MiniMax 是按席位——形态不同 |
| **凭证状态** | `PENDING_VALIDATION / ACTIVE / DRAINING / DISABLED / INVALID`（`CredentialStatus.java:5`） | `DRAINING` = 轮换中旧凭证只等存量请求跑完 |

### 3.2 授权与归属

| 概念 | 是什么 | 为什么要它 |
|---|---|---|
| **项目 Project** | 授权、用量、成本归集的核心实体，有 `code` 与 `project_tag`（路由标签） | 「哪个项目烧了多少 token」是产品第一诉求 |
| **Grant（项目授权）** | `ProjectProviderGrant` = **项目 × 上游凭证 × 供应商产品 × 允许的模型集合** | 管理员用它划定「这个项目能用什么」；用户只能在边界内建 Key，**不能自行扩大** |
| **key×project 绑定** | `key_project_binding` 一行 = 一个 (Key × 项目) 授权，**每行带自己的 `grant_id`**（V53） | 一把 Key 服务多项目（ADR-0018）；请求解析到哪一行，就用哪一行的凭证/产品/模型集 |
| **项目标签 project_tag** | 密钥后缀 `.proj-a` 对应的短标识，创建时由 `code` 派生、可被引用后**不可改** | 免改造的项目声明：同一把 Key 在不同客户端条目里加不同后缀即可 |
| **归属归因** | 请求级判定阶梯：`X-Miqro-Project-Id` 头 → 密钥后缀 → 唯一绑定 → `400 CONTEXT_REQUIRED` | 账要记给谁必须**确定性可复算**，绝不猜（详见 §5.2） |

### 3.3 治理

| 概念 | 是什么 | 为什么要它 |
|---|---|---|
| **用量事件 UsageEvent** | 每请求一条不可变事实：模型、Token（含缓存读写）、延迟、状态、错误分类、价格快照；**绝不含 prompt/正文** | 账单、配额、对账的唯一事实源 |
| **配额规则 QuotaRule** | 作用域(USER\|PROJECT) × 指标(TOKENS\|REQUESTS\|COST) × 周期(DAILY\|WEEKLY\|MONTHLY\|YEARLY) × 阈值 × 预警百分比 × 动作(`ALERT` 默认 / `REJECT`) | 从「只会记账」变成「会刹车」，但默认不刹车 |
| **API 消费者 ApiConsumer** | 外部系统的机器身份，凭据是 `mqk_api_…` 或 RS256 JWT | MCP 与计费查询的调用方不是人，不能发虚拟密钥 |
| **Agent（智能体）** | 一个把「出口凭证」命名化的托管实体；**不落独立用量维度**，用量按绑定凭证聚合出 Agent 视图 | 让「哪个自动化在花这笔钱」可命名、可停用、可追 |
| **MCP 服务** | 注册进来的 MCP Server（Streamable HTTP / SSE）+ 工具清单 + 访问控制 + 健康检查 | 让**模型通道不可改**的封闭客户端也能被纳管（§5.7） |
| **技能库 Skill** | Anthropic Agent Skills 格式的技能包目录，全员可见、**下载按团队/项目授权** | 内部能力分发，且分发本身可管控 |

### 3.4 平台不变量

- **单租户**：`tenant_id` 保留在核心表，首版固定一个租户，不实现 SaaS 租户管理（`docs/domain-model.md:27`）。
- **热路径零外部依赖**：网关不做数据库查询、不引 Redis；配置靠**路由快照**下发，秒级刷新。
- **审计链 append-only**：用量可以物理删除，**审计不删**。

## 4. 接入方怎么用：从零到跑通

这是本文最该照着做的部分。分成「管理员一次性准备」+「每位用户各自的 5 分钟」。

### 4.1 管理员准备（部署后只做一次）

> 目标：让任意成员都能自助建 Key。做完这 5 步即可。

1. **确认供应商产品** —— 左侧「模型管理 → 供应商」。每行是一个产品实例，列有协议、接入地址、
   实现状态、余额来源。行内「接入文档」直达该产品的官方端点说明。
   **注意**：徽章为「已验证」才建议承载生产流量；「已验证」需要真实凭证的契约测试。
2. **录入真实 Key** —— 「模型管理 → 上游凭证 → 录入凭证」。选订阅/产品，把官网申请的 Key
   粘进「API 密钥」（加密保存、不回显）。保存后点 **「验证」** 让网关真实调用供应商确认。
3. **建项目并拉人** —— 「访问与授权 → 项目 → 新建」（如 `core-ai`），在「成员」里加人。
   **用户必须至少属于一个项目才能建 Key。** 项目不填标签也没关系——标签会自动派生。
4. **建授权** —— 「访问与授权 → 授权 → 新建」：选项目 → 选凭证 → 勾选模型。
   这条 Grant 就是用户建 Key 时的选择范围。
5. **（可选）录模型目录** —— 供应商行「模型目录 → 探测模型」一键从官方拉取；
   没有公开模型列表接口的产品，按上游真实 `model` 名**手工补录**。

### 4.2 登录门户

打开 `https://<网关地址>`（与门户同域名）。

- 首次登录（或管理员重置后）会强制**设置新密码**，临时密码随即作废；
- 空闲 30 分钟失效，会话最长 12 小时；**被锁屏 ≠ 退出**；
- 服务重启时显示「服务不可用」重试页，点重试即可，**不需要重新登录**
  （`frontend/src/router/index.ts:287` 的 `unavailable` 分支）。

### 4.3 创建虚拟密钥（用户自助，免审批）

左侧「**我的密钥**」→ 右上「创建虚拟密钥」，填：

| 字段 | 填什么 | 例子 |
|---|---|---|
| 名称 | 好认的名字（建议按设备/用途区分） | `claude-code-笔记本` |
| 项目 | 你加入的项目；**可多选**（ADR-0018，首个为主项目） | `core-ai` |
| 供应商产品 / 授权 | 选管理员配好的授权（决定可用产品与凭证） | DeepSeek 授权 |
| 用途 | **纯声明标签**，只用于展示/审计与 CC Switch 目标推断，不限制客户端 | Claude Code |
| 允许模型 | 从该授权允许的模型里勾，至少一个 | `deepseek-flash` |
| 缓存策略 | 默认关闭；开启后同请求秒回（§5.4） | 关闭 |

点「创建」后 **密钥只显示一次**（`mqk_live_…`）。立刻复制保存——**丢了只能轮换**。

> 请求体契约：`CreateVirtualKeyRequest`（`projectId` 必填 + `projectIds` 可选多项目 + `providerProductId`
> + `credentialGrantId` + `purpose` + `allowedModels` + `cachePolicy`），
> `backend/control-plane-app/src/main/java/com/miqroera/miqrokey/controlplane/dto/CreateVirtualKeyRequest.java:31`。

### 4.4 填进 CC Switch（最省事的一条路）

在「我的密钥」目标行点「更多 ⌄ → 接入 CC Switch」，弹窗里：

1. 选目标应用（**Claude Code** 或 **Codex**；默认按密钥用途推断——`CODEX` 用途落 Codex，其余落 Claude Code）；
2. （可选）选默认模型 chips，会写进深链的 `model` 参数；
3. 点「导入」唤起 CC Switch，或点「复制深链」自行打开。

深链的真实形状（`frontend/src/lib/ccswitch.ts:66`）：

```text
ccswitch://v1/import?resource=provider&app=<claude|codex>&name=MiQroKey+·+<keyName>
  &endpoint=<baseUrl 或 baseUrl/v1>&homepage=<baseUrl>&apiKey=<mqk_live_…>&model=<模型>
```

**关键差异（照抄容易踩）**：

| app | `endpoint` 该填 | 为什么 |
|---|---|---|
| `claude` | 裸网关地址 `https://<网关地址>` | Claude Code 自己会拼 `/v1/messages` |
| `codex` | `https://<网关地址>/v1` | Codex 的 provider 模板固定 `wire_api = "responses"` 且会自己拼 `/responses`，所以必须带 `/v1` |

> 深链是**单向**协议：CC Switch 不回执是否导入成功。门户的反馈卡只是「唤起检测」，
> **不会**承诺导入成功（`docs/frontend-design.md:199`）。

### 4.5 手动接入（不走 CC Switch）

#### A. Claude Code / Claude Desktop（环境变量）

```bash
# macOS / Linux
export ANTHROPIC_BASE_URL="https://<网关地址>"
export ANTHROPIC_AUTH_TOKEN="mqk_live_…"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
```

# Windows PowerShell：$env:ANTHROPIC_BASE_URL="…" / $env:ANTHROPIC_AUTH_TOKEN="…"
# Windows CMD：       set ANTHROPIC_BASE_URL=…   / set ANTHROPIC_AUTH_TOKEN=…
```

> 三平台等价，源头 `frontend/src/lib/ccswitch.ts:106`。IDE 插件（VSCode/JetBrains）用
> `~/.claude/settings.json` 的 `env` 块，同一组键（`ccswitch.ts:129`）。

#### B. Codex CLI

`~/.codex/config.toml`（Windows 为 `%USERPROFILE%\.codex\config.toml`）：

```toml
model_provider = "miqrokey"
model = "deepseek-flash"

[model_providers.miqrokey]
name = "MiQroKey"
base_url = "https://<网关地址>/v1"
env_key = "MIQROKEY_API_KEY"
wire_api = "chat"
```

然后单独设环境变量 `MIQROKEY_API_KEY=<你的密钥>`。
**凭据刻意不写进 config.toml**——那个文件会被 grep、索引、备份、贴进工单（`ccswitch.ts:157`）。

若你偏好 `auth.json` 形态：把 `env_key` 行换成 `requires_openai_auth = true`，
并在 `~/.codex/auth.json` 写 `{"OPENAI_API_KEY": "<你的密钥>"}`（`ccswitch.ts:180`）。

#### C. 通用 OpenAI 兼容客户端 / curl

```bash
curl https://<网关地址>/v1/chat/completions \
  -H "Authorization: Bearer mqk_live_…" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"你好"}]}'
```

Base URL 填 `https://<网关地址>/v1`，API Key 填 `mqk_live_…`。

#### D. 数据面端点矩阵（同一入口，原样透传）

| 协议族 | 路径 | 典型客户端 |
|---|---|---|
| Anthropic Messages | `POST /v1/messages` | Claude Code / Claude Desktop / Anthropic SDK |

### 4.6 验证与观察

1. 第一条请求返回 200 即接入成功；
2. 回门户「用量」页，几分钟内能看到这次调用（入账有延迟，**不是实时**）；

4. 单项目 Key 自动归该项目；多项目 Key 见 §5.2。

### 4.7 排错对照表

| 现象 | 先查 | 说明 |
|---|---|---|
| 401 `invalid_api_key` | 密钥是否完整、`Bearer` 格式、Key 是否被停用 | MCP 面无效密钥返回 401 |
| **404 `virtual_key_invalid`** | 密钥值本身 | **`/v1` 面对无效密钥统一 404（防枚举）**——被吊销/轮换退役的旧 Key 也走这里，别当成「地址写错」 |
| 403 模型不可用 | 该模型是否在授权范围 | 去「模型申请」提交，管理员批准后**立即生效**，无需重建 Key |
| 403 `consumer_scope_denied` | 消费者是否勾了 `mcp:call` / `billing:read` | 能力**默认全拒** |
| 400 `CONTEXT_REQUIRED` | 多项目 Key 未声明项目 | 带 `X-Miqro-Project-Id` 或加后缀（§5.2） |
| 429 `quota_exceeded` | 命中 `REJECT` 配额规则 | 响应带 `Retry-After`；窗口重置或提额后**自动恢复** |
| 502（上游错误脱敏透传） | 供应商侧 | 本网关**不自动故障切换** |
| 504 `mcp_upstream_timeout` | MCP 上游预算（默认 60s） | —— |
| 413 | 请求体超限 | 反代 32MB 上限 |
| 一直转圈 | 网关到供应商的连通/超时预算 | 把 `requestId` 发给管理员 |

> **实测坑（已验证）**：上游 V4.1 系模型的思考预算与 `max_tokens` 同池——预算给小了会出现
> 「HTTP 200 + 空内容 + `finish_reason=length`」。**`max_tokens` 至少给 1024**（`docs/user-guide/developer-guide.md:124`）。

## 5. 功能全景

按域讲「**给谁解决什么**」。导航分组即架构：普通用户 9 个页面 + 管理员 7 组 28 个页面 = **37 个页面**
（`frontend/src/components/NewShell.vue:85-146`；路由 `frontend/src/router/index.ts:34-261`）。

### 5.1 密钥管理（`我的密钥` / `上游凭证` / `授权` / `API 消费者`）

**给谁**：普通用户（自助）；管理员（把边界划好）。

- **创建**：在授权边界内免审批。项目可多选。
- **轮换**：新密钥立即生效，旧版本进入**宽限期**后退役；轮换**复制全部项目绑定**（ADR-0018 D4），路由不受影响。
- **停用 / 启用**：**软停用**——绑定与授权原样保留，客户端表现为 404（无效 Key 统一语义）。
- **吊销**：不可逆，列表保留记录。
- **上游凭证**：录入 → 验证 → 轮换 → 停用。**删除/停用前先看引用计数**——凭证一旦从快照移除，
  关联虚拟密钥**立即无法完成请求**（秒级）。
- **API 消费者**：给外部系统的机器身份。新建时一次性展示 API Key，或配置 **JWT 公钥**（RS256，
  `sub` claim = 消费者名）。能力作用域 `billing:read` / `mcp:call` **默认全拒**，须显式勾选
  （`backend/domain/src/main/java/com/miqroera/miqrokey/domain/model/ConsumerCapabilities.java:16-17`）。

### 5.2 归属：这笔账记给谁

**给谁**：所有做成本分摊的人。这是本系统最容易讲错的一块，单独成节。

判定阶梯是**确定性、无启发式**的（`backend/gateway-app/src/main/java/com/miqroera/miqrokey/gateway/vkey/RequestContextResolver.java:19-32`）：

1. `X-Miqro-Project-Id` 头（必须 UUID，且 Key 对该项目有 ACTIVE 绑定）→ 否则 400 `CONTEXT_INVALID` / 403 `CONTEXT_NOT_ALLOWED`；
2. **密钥后缀**（`.proj-a`）匹配某个绑定 → 命中；**后缀不匹配是装饰性的**，继续往下走；
3. **恰好一个** ACTIVE 绑定 → 无歧义，直接归属；
4. 零绑定 → 无效 Key（统一 404）；**多绑定且无上下文 → 400 `CONTEXT_REQUIRED`**（宁可拒绝，绝不借用别的项目的凭证）。

**三种用法**：

| 场景 | 怎么做 |
|---|---|
| 一把 Key 一个项目 | 什么都不用做（阶梯第 3 条） |
| 一把 Key 多项目、客户端可配 | 每个项目在客户端建一个条目，密钥串加对应后缀；或带 `X-Miqro-Project-Id` 头 |
| 一把 Key 多项目、想零配置 | 装本机 `miqro-context` Agent，按工作目录/仓库自动判定 |

> **明确不做**：**不看内容推断归属**。理由是分摊/对账必须确定性、可复算，概率性归属不能入账
> （ADR-0018 D8）。这是红线，不是待办。

### 5.3 用量与配额

**用量（用户视角）**：只看自己名下 Key 的消耗。筛选（时间/模型/Key）+ 汇总（请求数、Token 输入/输出/缓存、延迟）
+ 逐条明细。**明细不含提示词与回答正文**——设计如此。

**用量报表（管理员）**：维度切换（项目/用户/团队/模型/供应商）、时间范围、请求时间线（含超长上下文截断标记）、
明细可导出 CSV。另有**用量删除**（按时间窗**物理删除**原始用量；删除动作本身与审计链永久保留）与**导出任务**。

**配额规则**：「给谁刹车」的核心。

| 维度 | 取值（代码） |
|---|---|
| 作用域 | `USER` / `PROJECT`（`QuotaScopeType.java:9`） |
| 指标 | `TOKENS` / `REQUESTS` / `COST`（`QuotaMetric.java:12`） |
| 周期 | `DAILY` / `WEEKLY` / `MONTHLY` / `YEARLY`（`QuotaPeriod.java:10`） |
| 动作 | `ALERT`（默认，只告警）/ `REJECT`（超限拒绝）（`QuotaAction.java:12`） |

- `REJECT` 命中 → HTTP **429** + `Retry-After`（该作用域最早可自愈窗口的结束时刻）。
  **Key 不失效、不自动禁用、不删数据**；恢复路径只有「跨入新窗口」或「管理员提额」（ADR-0020 D2）。
- 判定按 **scope 而非按 Key**——同一用户/项目下的其余 Key 一并生效。
- **近似语义（已对客户承诺）**：控制面每 60s 评估一次，判定集**不包含评估周期内新产生的用量**；
  「卡在恰好 100%」不可承诺，页面与网关可能有一个周期的不一致（ADR-0020 D5）。
- **刻意不做**：速率限流（RPM/TPM）不在此列——配额管「这月能用多少」，限流管「此刻能跑多猛」，是两件事
  （ADR-0026，状态 **Proposed，未实施**）。

**月度预算**（`budgets`）：按项目配月度额度水位，**alerting only — never blocking**
（`AdminBudgetController.java:28-31` 的类注释即原文）。它与配额规则的 `REJECT` 是两套东西，不要混。

### 5.4 成本、对账、定价、缓存收益

**给谁**：管理员与财务口径。

| 功能 | 解决什么 |
|---|---|
| **成本报表** | 按调用方/项目/模型看成本构成，以及「网关观测成本 vs 上游实付」 |
| **账单对账** | 上传供应商 canonical JSONL 账单 → 四级匹配（request id 精确 → 指纹+模型+时间 → token/状态/费用组合 → 5 分钟桶聚合）→ **四态报告**（`MATCHED` / `PARTIAL` / `UNMATCHED_PROVIDER` / `UNMATCHED_LOCAL`）+ 金额差 |
| **定价** | 按（产品、模型、Token 类型）维护每百万 Token 单价（CNY）。**单价是不可变快照**——改价即追加，历史成本不重算。新模型未定价时成本显示「未定价」，录价后自动入账 |
| **缓存收益（ROI）** | 总请求、L1/L2 命中、命中率、节省金额与等效折扣——判断缓存策略值不值得继续 |

**响应缓存**（ADR-0009）：

- **L1 = Caffeine 进程内缓存；L2 = PostgreSQL `cache_entry` 精确缓存**
  （命名以代码为准，ADR-0009 的订正段已说明历史措辞有误）；
- **双重 opt-in**：Key `cachePolicy=ENABLED` **且** 客户端显式带 `X-MiQroKey-Cacheable: 1`，默认全关；
- 命中时响应带 `X-MiQroKey-Cache` 头；
- **含 `tools` 的请求永不缓存**（工具调用有副作用）；语义缓存不启用（见 §7-8）。

### 5.5 内容留痕（合规能力，默认关闭）

**给谁**：有内容合规审查需求的部署方。

- **默认全关**：`RetentionConfig` 的注释原文是「Everything is DEFAULT OFF: a missing row means no
  request content is ever collected」（`backend/domain/.../RetentionConfig.java:5-8`）。
  **不开则永不留存正文**——这不是配置项，是承诺。
- 开启后：用户输入文本（`INPUT`）与模型回复文本（`OUTPUT`）分别加密成**密文信封**落事件流；
  可设最大截断字节数（默认 256 KiB，范围 1 KiB–4 MiB）。
- **工具调用载荷、系统提示词、推理链（reasoning）仍不采集。**
- **查看/导出本身会被审计**（受权读者路径）。
- 传输形态是 Kafka 事件流（topic 按 user hash 分区），冷存目标是对象存储 + SSE-KMS，
  消费端参考实现见 `docs/retention-consumer.md`。
- **开启属合规决策**——与法务确认后再启用。

### 5.6 模型目录与供应商接入

**给谁**：管理员接供应商；普通用户看能用什么。

- **供应商页**：每行一个产品实例，行内「接入文档」「模型目录」「试调」。**「试调」**= 用该产品首个生效凭证
  发一条真实消息（≤256 token，**正文不落库**）。实现状态阶梯：已文档化 → 已实现 → **已验证**——
  **未验证的产品不建议承载生产流量**。
- **模型目录**：探测（从官方拉）或手工补录。探测失败不会破坏现有目录。
- **模型广场**（用户侧）：自查可用模型 + 单价（只读元数据）。
- **试调台**（用户侧）：粘贴自己的虚拟密钥，发一条 `stream=false`、≤512 token 的试调；密钥**只存内存**。
- **模型申请**：用户申请未覆盖的模型 → 管理员在「审批中心」处理 → 通过后**并入该 Key 的授权、立即生效**，
  无需重建 Key。**给已轮换/吊销的 Key 提交的申请会被系统拒绝（提示改为驳回）——不要硬批。**

### 5.7 MCP 代理（工具生态纳管）

**给谁**：模型通道**不可改**的封闭客户端——它们的模型对话进不了网关，但 MCP 配置往往可改。

- **服务级访问控制**：`McpAclMode` = `NONE`（开放，可在工具级细化）/ `ALLOW`（仅名单）/ `DENY`（名单外）
  （`backend/domain/src/main/java/com/miqroera/miqrokey/domain/model/McpAclMode.java:10`），
  叠加**单工具覆盖**。
- **凭据**：用 **API 消费者的 Key**（不是虚拟密钥），必须勾 `mcp:call`。
- **韧性策略** + 健康检查（默认 30s 探 `/health`）+ 手动上下线。
- **MCP 访问日志**：逐调用记录工具名、消费者、TTFB、结论——**仅元数据**。
- 「接入信息」直接给出 `streamableHttpUrl` / `sseUrl` 供粘贴。
- **实测样章**（真实封闭客户端全流程 + 踩坑）：`docs/workbuddy-mcp-onboarding-sample.md`。

> **边界**：这条姿势**只覆盖该工具的工具生态**——它的模型对话仍走平台通道，**不进网关账本**
> （`docs/client-onboarding.md:75`）。

### 5.8 审计、告警、可观测

| 功能 | 给谁解决什么 |
|---|---|
| **审计日志** | 全部管理动作：谁、何时、对什么、结果，含 from/to 变更明细；按动作/目标/时间过滤。**append-only 哈希链，设计上不可删** |
| **告警规则** | 阈值 → Webhook 通道；支持测试发送 |

**告警覆盖范围**（`docs/product-requirements.md:111-120`）：凭证验证失败/失效、供应商错误率升高、

> **告警与阻断是分开的**：告警**不阻断**请求；唯一会阻断的是配额规则里显式标为 `REJECT` 的那条。

## 6. 管理员日常要做什么

### 6.1 巡检清单（先看这个）

| 频率 | 看哪里 | 看什么 |
|---|---|---|
| 每日 | 总览 / 缓存收益 | 异常事件、失败率、缓存省钱趋势 |
| 每周 | 成本报表 → 账单对账 | 上游实付 vs 网关观测成本、对账差异 |
| 每周 | 配额规则 | 谁在接近阈值（列表百分比 + Webhook） |
| 按需 | 审计日志 / 内容留痕 | 操作留痕；内容留痕**仅在有合规要求时开** |
| 按需 | 供应商 / 上游凭证 | 凭证健康（最近验证）、余额来源 |

### 6.2 四类典型动作

**① 建项目 / 团队 / 用户**

1. 「访问与授权 → 用户 → 新建」→ 生成**一次性临时密码**，关闭弹窗前交付本人；
   「重置密码」会重新签发并让旧会话失效；「禁用」立即停登录并踢出现有会话（**可逆**）。
2. 「团队」= 组织标签（N:M，可一人多团队），**不承担授权**。
3. 「项目」= 权限载体。有「路由标签」（`project_tag`）：**被任何密钥绑定引用后不可改**
   （改会返回 409 `PROJECT_TAG_IN_USE`，并给出受影响绑定计数）。不填也会自动派生。
4. 项目行内「成员」抽屉增删成员 → **用户必须至少属于一个项目才能建 Key**。
   移除成员会**按项目粒度**禁用其 Key 在该项目的绑定（ADR-0018 D7）。

**② 配供应商凭证**

1. 「模型管理 → 供应商」确认产品与协议；
2. 「上游凭证 → 录入凭证」粘真实 Key（加密、不回显）→ **点「验证」**；
3. 「订阅」管理套餐形态（席位、共享池、周期）；
4. 「授权」把 项目 × 凭证 × 模型 串起来——**这是用户能建 Key 的前提**；
5. 轮换用行内「轮换」（新密钥立即生效、旧版本 `DRAINING` → 宽限后退役）；
   **泄露时先「停用」止损，确认新 Key 上线后再考虑吊销**。

**③ 定配额**

- 规则 = 作用域 × 指标 × 周期 × 阈值 × 动作。
- 例：测试账号 → `REQUESTS / DAILY / 2000 / 仅预警`；对外演示项目 → `COST / MONTHLY / 500 元 / 超限拒绝`。
- **默认永远是 `ALERT`**；开 `REJECT` 是有意的选择，且**可随时停用或删除该规则立即解除**。
- 可用「配额默认模板」让新建作用域自动带上默认规则。

**④ 看审计 / 处理异常**

- 「审计日志」按动作/目标/时间过滤，看 from/to 变更明细；异常请求拿 `requestId` 在审计/日志侧定位同一请求；
- 供应商故障：**网关不会自动切换**——按 `docs/operations-runbook.md` §5 的流程处理；
- 用量异常：先看配额水位与「用量报表」时间线，必要时用「用量删除」清理（**先导出备份**——删除后对账与成本报表同步变化）。

### 6.3 推荐实践

- **环境隔离**：演示/测试/生产分实例部署，各自独立的凭证与配额；
- **最小权限**：每个业务线单独建项目与授权，不要共享一把 Key 跨业务；
- **凭证轮换**：上游凭证与虚拟密钥季度轮换；
- **审计留档**：每月导出一次审计日志与成本报表归档；
- **内容合规**：确需内容审核时才开留痕，并同步配置消费端。

## 7. 明确的边界（设计红线）

**这一节是给接手人防走弯路的**——下面每一条都是**有意的设计决定**，不是未完成的缺口。
如果你接手后想改，先看对应的 ADR 并新开 ADR，不要当 bug 修。

| # | 不做 | 为什么 / 出处 |
|---|---|---|
| 1 | **不做跨协议转换**（Anthropic ↔ OpenAI ↔ Gemini） | 协议转换归客户端侧（CC Switch）；重复实现会破坏工具调用、推理字段与 prompt cache。ADR-0002 |
| 2 | **不自动跨供应商故障切换**；首字节前最多安全重试一次，流开始后不重试 | ADR-0021 §1.1 记录了原决策；`docs/ai-gateway-comparison.md` 标为「刻意差异」 |
| 3 | **不做供应商之间的自动路由 / 负载均衡 / 按价格速度质量选模型** | `product-requirements.md:27` 非目标 |
| 4 | **不保存请求与响应正文**（默认） | 唯一例外 = 管理员显式开启的内容留痕（ADR-0014）；日志、审计、缓存、错误体都不含正文 |
| 5 | **不做内容推断归属**（拦截问答、按内容判项目） | 财务分摊必须确定性可复算；且与「不读正文」承诺相悖。ADR-0018 D8 |
| 6 | **不做速率限流**（RPM/TPM/令牌桶） | 与长任务结构性冲突；ADR-0026 状态 **Proposed，未实施**，现行边界 = 不做 |
| 7 | **不做预算硬熔断**（`budgets` 只告警） | `AdminBudgetController` 类注释原文「alerting only — never blocking」 |
| 8 | **不做语义缓存 / 向量召回** | 依赖向量库，违反「不引中间件」；ADR-0009、ADR-0022 |
| 9 | **不做多租户 SaaS** | `tenant_id` 保留但首版固定单租户。`domain-model.md:27` |
| 10 | **不做硬限流式的自动禁用 Key** | owner 明确否决（误伤面大、不可逆）；配额超限走 429，不动 Key 状态。ADR-0020 §3-B |
| 11 | **不引 Redis / 消息中间件到热路径** | ADR-0005；网关热路径零查询、零计数、零算术 |
| 12 | **不为 CC Switch 生成配置文件** | 只发深链，落盘由 CC Switch 自己完成 |
| 13 | **不做网络层劫持**（hosts + 本地代理 + 自签证书）撬开封闭客户端 | 成本高、有 TLS 与合规风险——不做，也不建议。`client-onboarding.md:105` |
| 14 | **不自动导入供应商账单、不自动完成对账** | 对账是「上传 canonical 账单 → 出报告」的人工流程。`product-requirements.md:33` |
| 15 | **审计链不可删** | append-only 哈希链；用量可删，审计不删 |

**另有两条容易被误当成缺口的**：

- **MCP 面不适用配额规则的 `USER`/`PROJECT` 作用域**——MCP 的调用方是 API 消费者，配额维度未覆盖它（ADR-0020 D6）。
- **被拒的请求不产生用量事件**——429 只进网关日志，不写 `usage_event`。这是既有口径。
