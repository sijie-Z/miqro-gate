## 一、项目是什么

### 1.1 定位

面向企业内部 AI 编程场景的**凭证虚拟化与用量治理系统**。用户在门户自助创建 Virtual Key → 把 `Base URL` + `Virtual Key` 填入 CC Switch → 由 CC Switch 配置 Claude Code / Claude Desktop / Codex。

### 1.2 明确不做什么（重要，别走弯路）

- **不是智能路由平台**，不是模型聚合中转站
- **不做跨协议转换**——网关保持上游协议透明，协议转换和模型映射由 **CC Switch** 完成（ADR-0002）
- 每个 Virtual Key 固定绑定项目 + 供应商产品 + 真实凭证（ADR-0018 修订为可多绑定，见下）
- 单客户、私有化部署、客户自行运维；首版按 **50 账号 / 50 条并发流式请求**设计

### 1.3 与 8 月设计文档的关系

`D:\Desktop\MiQroKey\` 下那套文档（架构设计报告 26 页 + 开发设计文档 + 交接说明，2026-08-14 交付）是**设计阶段产物**，本项目是其实现。两者基本对应，但实现过程中有若干决策调整（以 ADR 为准，见第十一章）。

## 二、技术栈与架构

### 2.1 技术栈

| 层 | 技术 |
|---|---|
| 语言/框架 | Java 21、Spring Boot 3 |
| 数据面 | Spring **WebFlux** + Reactor Netty（`gateway-app`） |
| 控制面 | Spring **MVC** + Spring JDBC（`control-plane-app`）— ADR-0006 |
| 前端 | Vue 3 + TypeScript + Vite + Pinia + **TDesign** |
| 数据库 | PostgreSQL 17.6（最低 16+）+ Flyway 迁移 |
| 部署 | Linux Docker Compose 单机 |

**明确不依赖**：Redis（ADR-0005）、LiteLLM/Bifrost 运行时（ADR-0004）。

### 2.2 后端 10 个 Maven 模块

| 模块 | 职责 | main/test 文件数 |
|---|---|---|
| `backend/domain` | 纯领域模型（无 Spring/DB/HTTP） | 162 / 13 |
| `backend/provider-spi` | 供应商/协议/余额/目录 SPI | 28 / 3 |
| `backend/provider-adapters` | 签名目录（Ed25519）+ 编译期适配器注册 | 28 / 22 |
| `backend/gateway-app` | WebFlux 推理数据面（代理/MCP/缓存） | 47 / 40 |
| `backend/control-plane-app` | 管理/门户/导出/告警 API | 199 / 117 |
| `backend/persistence-postgres` | JDBC 仓储 + Flyway | 45 / 14 |
| `backend/route-snapshot` | 版本化只读路由快照 | 7 / 2 |
| `backend/queue-spi` | 有界用量写入队列 SPI | 9 / 2 |
| `backend/cache-spi` | 响应缓存 SPI + NoOp（ADR-0009） | 6 / 0 |
| `backend/test-support` | Mock Provider 与契约测试工具 | 14 / 3 |

### 2.3 数据面关键机制（理解这个就看懂了架构）

**版本化只读路由快照**：
- 热路径**零 DB 访问**，只做内存查询 + AES-256-GCM 解密
- 控制面事务提交后 `pg_notify miqrokey_route_refresh` → 网关 LISTEN 即时重载
- 丢通知由 30s 定时刷新兜底
- 详见 `docs/architecture.md` §3、§4.1

### 8.2 部署形态

Linux Docker Compose 单机（`deploy/compose.yaml`）：
```
reverse-proxy → control-plane / gateway / Vue 静态页 + PostgreSQL
```
- **无 Redis**；Prometheus + Grafana 仅可选 profile
- 发布前先 `docker compose config` 校验
- 启动顺序：PostgreSQL 健康 → control-plane/gateway/portal
- 发布后按**六步闭环冒烟**：注册 → 加入项目 → 建 Key → 真实推理 → 用量核对

### 8.3 备份与恢复（`deploy/backup/`）

- 每日 02:00 cron → `miqrokey-backup.sh`（pg_dump → gzip → AES-256-CBC/PBKDF2 200k → `<时间戳>.sql.gz.enc` + SHA-256 manifest）

## 九、运维要点

### 9.1 密钥轮换（高风险操作）

**`POST /api/v1/admin/crypto/reencrypt`** — 幂等，重复调用至 `remaining = 0` 才可退役旧 key。

> ⚠️ **HMAC key 不可重算摘要**——退役旧版本前**必须重发所有该版本签发的 Virtual Key**。
> ⚠️ **master key 丢失 = 真实凭证不可恢复**。

### 9.2 三类凭据 401 归因（运维最常踩，runbook §14.1）

| 凭据 | 前缀 | 只认哪些面 |
|---|---|---|
| Virtual Key | `mqk_live_` | 只认推理面 |
| 消费者 Key | `mqk_api_` | 只认计费/MCP 面 |
| 消费者 JWT | 三段式 | 各面按需 |

**端点各认各的，混用一律 401。**

### 9.3 排障要点

- **429 只可能来自上游**（本系统不限流）
- **403 全部来自本系统授权层**（按 error code 归因）
- 供应商账单 **T+1 才稳定**，对账窗口取 T-1 及更早
- **usage 队列 drop 必须恒为 0**（`/actuator/prometheus` 观察，soak 有硬断言）

### 9.4 已知坑

- 本机备份不防主机损坏
- **2G 演示机**需 JVM 限堆/SerialGC + portal 串行 typecheck+build（#667/#679）
- Windows 下 `miqro-local/` 是本地脚本区（已被 .gitignore）

## 十一、关键设计决策（ADR 全表）

| ADR | 结论 |
|---|---|
| 0001 | Java 21 + Spring Boot 3 + WebFlux + Vue 3 + PostgreSQL，符合客户维护能力 |
| 0002 | **透明代理**：Gateway 只做鉴权/凭证替换/固定转发/用量解析，不做跨协议转换（CC Switch 职责） |
| 0003 | v1 不做响应缓存（**已被 0009 取代**） |
| 0004 | 生产不依赖 LiteLLM/Bifrost，供应链风险过高 |
| 0005 | v1 不引 Redis，只用 PostgreSQL，热路径靠版本化只读快照 |
| 0006 | gateway 用 WebFlux、control-plane 用 MVC+JDBC，独立部署 |
| 0007 | 统一产品名/包名/Key 前缀/环境变量前缀，禁止别名 |
| **0008** | **⚠️ 文件不存在**（D01 缺口） |
| 0009 | **取代 0003**：启用 L1 精确缓存（PostgreSQL `cache_entry`），双重 opt-in 默认全关、工具调用永不缓存 |
| 0010 | 新增 `mqk_api_` API Key（只存 SHA-256）保护 `/api/v1/billing/**` 只读查询 |
| 0011 | 消费者 JWT：RS256、平台自持私钥、网关只存验签公钥；范围后扩到 MCP 数据面 |
| 0012 | Kafka 引入，首个场景=内容留痕事件管道；queue-spi 维持「PG 主写 + Kafka 仅扇出」 |
| 0013 | MCP 调用代理选案 B：消费者 Key 摘要进只读快照 + 服务/工具两级 ACL |
| 0014 | 内容留痕 + Kafka + OAuth 映射；**显式放宽「不存正文」红线**，新增默认关闭的密文留痕通道 |
| 0015 | 管理开放 API 机器凭据 `mqk_admin_`：只存摘要、Bearer、豁免 CSRF；先只读子集 |
| 0016 | 写面机器执行者语义（A+C）：无执行者列的配置写面直开、需执行者列的走委托 |
| 0017 | 平台 OIDC 登录：授权码 RP 登录，`sub` 经 `user_identity_link` 映射建门户会话 |
| **0018** | **单密钥多项目**：修订「一 Key 固定一个项目」→ key×project 多绑定（V53），后缀=每次使用时的项目选择器，轮换复制全部绑定，模型门控改用绑定 grant，明确不做内容推断 |
