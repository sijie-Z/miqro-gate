### `views/next/` 的「next」是什么意思？

**是已经过期的历史命名，不是「下一代/未来版本」。** 证据链：

1. `docs/progress.md:967` 记录了当时的执行路线：「tokens v2（新语义名，不覆盖 v1 值）→ `frontend/src/ui/` 自绘组件 → **`/app-new/*` 平行路由（保留 TDesign 版对照）** → 试点 Login/Keys/Usage/AdminUsers」。
   所以 `next` = **U0/U1 期「v2 自绘控制台」，与 TDesign 旧版并行存在的那一套**，路由前缀 `/app-new`。
2. `src/router/index.ts:246-249`：
   ```ts
   // Pilot prefix retired in U1-2 — old pilot URLs keep working via redirect.
   path: '/app-new/:pathMatch(.*)*',
   redirect: (to) => '/app' + to.path.slice('/app-new'.length),
   ```
   试点前缀在 **U1-2 已退役**。
3. 旧版已经删干净：`frontend/src/views/` 下只剩 `next/`；`frontend/src/components/` 下只有 `NewShell.vue`，**没有 `AppShell.vue`**；`frontend/package.json:21-27` 的 dependencies 里没有 `tdesign-vue-next`。
4. `src/__tests__/ui-layer.spec.ts:16-18` 用一条断言把这件事钉死：`src/**/*.{vue,ts}` 中不得出现 `from 'tdesign-vue-next'`（`tdesign-icons-vue-next` 作为图标资源库被显式豁免，见该文件 `:7-10` 的注释）。

**结论**：接手时把 `views/next/` 当作「唯一的页面目录」用，命名只是没改名；新增页面照旧放 `views/next/`。

### 2.7 Shell 标签页与导航的 URL 语义（`components/NewShell.vue`）

**导航身份只有 `route.name`，但筛选状态活在 URL query 里**。典型现场：上游凭证列表把 `?credentialId=` 深链进授权页，而授权页的筛选**完全从 URL 推导**（`NextGrantsView.vue:174-182` 只 `import { useRoute }`、从不回写 URL）—— 此时若只按 `name` 跳转，点标签栏或左侧导航（**包括点自己已高亮的那一项**）会**静默清空筛选**。当前实现：

| 关注点 | 现在的做法 | 位置 |
|---|---|---|
| 标签目标 | `ShellTab` 带 `fullPath`；`tabTarget()` 返回 `fullPath ?? { name }` | `:195`、`:273-275` |
| 路由监听 | watch 盯 `route.fullPath`（query-only 变化也更新目标） | `:251-266` |
| 点击标签 | `activateTab()` **不做「已是当前项就早退」** —— 重复导航由 vue-router 丢弃，早退反而会吞掉飞行中的点击 | `:282-284` |
| 点击侧栏 | `navTarget()`：当前项返回 `route.fullPath`（同址导航被 vue-router 当重复导航忽略 → query 保住）；其它项走裸路由 | `:291-293` |
| 侧栏语义 | **「去某个分区」，不是「复活该分区上次的筛选」** | — |
| 持久化 | sessionStorage **只存 `{name,label}`**（`slice(-24)` 截断） | `:238-243` |
| 恢复 | `restoreTabs()` 用 `router.hasRoute(tab.name)` 滤掉解析不出的名字，并按 `slice(-24)` 截断 | `:214-227` |

两条不能破的约束：① **sessionStorage 跨登出存活** —— 存 `fullPath` 等于把上一个用户的 `?credentialId=` 交给下一个登录者，所以持久化只存 `{name,label}`；② 恢复时必须滤掉会话里解析不出的 `name` —— 否则会渲染成普通标签、点下去同步抛 `MATCHER_NOT_FOUND`，`void push()` 接不住的**死按钮**（手改的 payload 也不能决定渲染多少标签，故 `slice(-24)`）。
测试：`src/__tests__/shell-tab-query.spec.ts`（真实 router + memory history 挂真实 `NewShell`，7 例）。

**`getList<T>()` 为什么存在**：`response.json() as T` 是无检查的断言，声明的形状只是承诺、不是保证 —— 非数组响应体（契约漂移 / 代理错误页 / 版本不匹配）会一路走到 `list.length` / `.map` 并在**渲染中途**抛错。`getList` 在**一处**归一化，让每个 list 端点的 `Promise<T[]>` 都诚实：

```ts
export function getList<T>(path: string, query?: RequestOptions['query']): Promise<T[]> {
  return get<T[] | null>(path, query).then((value) => (Array.isArray(value) ? value : []));
}
```

**约定：新增 list 端点一律用 `getList<X>`，不要用 `get<X[]>`**（`api/index.ts` 现有 **39 处**）。配套守卫 `src/__tests__/null-list-render.spec.ts`（10 个参数化用例，各自动态 `import()` 一个视图再 mount —— 契约漂移下这些页面必须仍能渲染）。

**没有 API Key / JWT / Bearer 注入** —— 管理 API 全程走门户会话 Cookie（`docs/api-contract.md:8`、`:111`：`MIQROKEY_SESSION`，HttpOnly + SameSite=Strict）。虚拟 Key / 消费者 JWT 都是**被管理的业务数据**，不参与前端自身认证。

### 3.3 错误处理：**没有全局拦截器**，逐 view 自理

⚠️ **关键事实**：全 `src/` 下对 `401` 的**唯一**处理在 `src/stores/auth.ts:25-28`：

```ts
/** A 401 is the only definitive "the session is gone" signal. */
function isUnauthorized(error: unknown): boolean {
  return error instanceof ApiError && error.status === 401;
}
```
它只在 `fetchMe()`（会话恢复）里被调用（`src/stores/auth.ts:58`）。**会话中途过期时没有自动跳登录页**——页面自己的 `catch` 会 `toast.error` 一条消息后停在那里。若要加全局 401 跳转，`src/api/http.ts` 的 `request()` 是唯一的注入点。

各 view 的统一写法（31 个 view `import { ApiError } from '@/api/http'`，23 个用 `toast.error`）：

```ts
} catch (error) {
  if (error instanceof ApiError) {
    toast.error(`${error.message}（requestId: ${error.requestId ?? '-'}）`);
  }
}
```
代表：`src/views/next/NextKeysView.vue:555-558`、`:617-620`。所有面向用户的错误串都带 `requestId`，是排障入口。

> 控制面写面校验已补齐（400 点名具体字段，而不是 409 / 500）—— 前端因此拿到的多是**可直接展示**的 `message`，各 view 的 `catch` 保持薄薄一层即可。

### 8.2 为什么 portal 构建改成「串行 typecheck + build」

**这是部署期的 OOM 修复，不是随手改的。**

`README` 即证据 —— `deploy/docker/portal.Dockerfile:12-15`：
```dockerfile
# npm run build 走 run-p 并行 vue-tsc+vite——实测峰值 ~1.3G，2G 演示机整机被打进
# swap 导致部署期全站超时（#667）；改为串行，峰值 ≈ max(两者) ≈ 740MB。

```

要点：
- `package.json:9` 的 `build` 仍是**并行** `run-p`（本地/CI 用，CI runner 内存充足）。
- Docker 镜像里改用 `&&` 串行，峰值从 ~1.3G 降到 ~740MB。
- ⚠️ 副作用：镜像里**先 build 后 typecheck**，两者的失败顺序与本地相反。

## 10. 如何新增一个页面（完整步骤）

以新增「模型用量趋势页 `/app/model-trends`（管理端）」为例。

**① 加 API 函数** —— `src/api/index.ts`
在合适的业务分节里加薄包装（不要在这里写业务逻辑）：
```ts
export function adminModelTrend(days = 30): Promise<ModelTrendReport> {
  return get<ModelTrendReport>('/api/v1/admin/usage/model-trend', { days });
}
```
- 若后端已把该 DTO 放进 OpenAPI：先在 `src/types/generated-api.ts` 加一行 alias
  `export type ModelTrendReport = components['schemas']['ModelTrendReportView'];`
  （名字不同就按 §4.2 的翻译职责处理），再在 `src/api/index.ts` 的 type import 块（`:20-77`）里补上。
- 若后端**还没有**这个 schema：在 `src/api/index.ts` 里就地写 `export interface`（跟 `ApiConsumerActivity` `:544-554` 一样），**不要**往 `src/types/api.ts` 里加——那个文件已是遗留，且 codegen 守卫会盯着它。
- 请求 DTO 也可以直接内联 `components['schemas']['X']`（照 `:82-89`）。

**② 生成/校验类型** —— `npm run gen:types`
⚠️ 若 `docs/openapi/openapi-3.1.json` 还没更新，这一步不会带来新 schema——**必须先在 Java 侧加 OpenAPI 注解并重新导出 spec**。CI 会跑 `gen:types && git diff --exit-code`（`.github/workflows/ci.yml:264`），提交前务必本地跑一次并一起提交 `src/types/generated.ts`。

**③ 写视图组件** —— `src/views/next/NextModelTrendsView.vue`
- 文件名 `Next*.vue`，放 `src/views/next/`（**没有其他视图目录**）。
- 顶部写文件头注释，格式照抄同目录现有文件（`* NextModelTrendsView — /app/model-trends v2 admin page.` + 一段行为说明）——**注意别写 `/app-new/...`**（见 §11.4）。
- 统一从 `@/ui` 导入组件，禁止深路径；页面骨架用 `design-base.css` 的 `.ui-page` / `.ui-page-header` / `.ui-page-title` / `.ui-page-desc` 类。
- ⚠️ **模板必须恰好一个元素根**（硬约束，不是风格问题）。需要多个顶层弹层时把它们**嵌进页面根 `div` 内**（`UiDialog` / `UiDrawer` 反正都 `Teleport` 到 body，占位只是锚点）；`v-else` / `v-else-if` 分支归并到前一根，算单根。违反的后果与守卫见 §12.2。
- 数据加载 + 错误的固定写法：
  ```ts
  import * as api from '@/api';
  import { ApiError } from '@/api/http';
  import { toast } from '@/ui';

  const loading = ref(false);
  async function load() {
    loading.value = true;
    try { data.value = await api.adminModelTrend(); }
    catch (error) {
      if (error instanceof ApiError) toast.error(`${error.message}（requestId: ${error.requestId ?? '-'}）`);
    } finally { loading.value = false; }
  }
  onMounted(load);
  ```
- 有操作步骤就把指引写进 `src/content/pageGuides.ts`，然后在页面里 `<UiPageGuide :guide="MODEL_TRENDS_GUIDE" storage-key="model-trends" />`。
- ⚠️ 页面级加载之外的**异步引用列表 / 选择器 / 面板**（下拉里要填的项目、团队、用户…）必须按 **§12.1 的规范模式**写：独立的 `loading` + `error` ref、渲染顺序「有数据 → 失败 → 加载中 → 空态」、失败可重试且不牵连页面级错误。**这一条是硬性验收项** —— 守卫 `silent-clear-empty-states.spec.ts` 会扫。
- 新增中文文案若要支持英文，在 `src/i18n/dict.ts` 的 `DICT` 里加 zh→en 条目（DOM 翻译层在 `src/i18n/index.ts`）。

**④ 挂路由** —— `src/router/index.ts`
在 `/app` 的 `children` 里加（管理端用 `adminMeta`，注意**按导航分组位置插入**）：
```ts
{
  path: 'model-trends',
  name: 'model-trends',
  component: () => import('@/views/next/NextModelTrendsView.vue'),

```
管理端还要加导航项，否则菜单里看不到：`src/components/NewShell.vue` 的对应分组数组（如 `usageQuotaNav`，`:111-117`）加 `{ name: 'model-trends', label: '模型趋势', icon: ChartBarIcon }`。
**面包屑自动生效**（`NewShell.vue:147` 注释 + `:151-162` 的 `breadcrumb` computed 从 `navGroups` 反查），但只有进了分组数组的页面才有面包屑。

**⑤ 用户自助端注意**
自助端页面用 `meta: { title: '…' }`（不要 `adminMeta`），并放进 `regularNav`。守卫会自动把非 `SYSTEM_ADMIN` 从管理端路由弹回 `/app/keys`（`router/index.ts:292-294`）。

**⑥ 写测试** —— `src/__tests__/NextModelTrendsView.spec.ts`

## 12. 前端健壮性：失败、空与异步（接手必读）

三条主线，同一个教训：**「没读到」不是「没有」**、**组件的根数是硬约束不是风格**、**失败不是终态**。写任何列表 / 选择器 / 轮询之前先读完本章。

### 12.1 「失败的加载不得渲染成数据」——一条贯穿式契约

同一条根因在四个地方以四种面孔出现过（表格 / 统计卡 / 计数器 / 引用列表）—— 它极容易复发。四个面：

| 面 | 修法落点 |
|---|---|
| 表格空态 | `UiTable` 的 `error` 属性（`src/ui/Table.vue:59`），错误优先于空态并自带重试按钮（`:220-238`） |
| 统计卡 | 加载失败显示 `—`，不画确定的 `0`（概览页与成本报表） |
| 计数器 | `countWhenLoaded(loadError, n)`（`src/utils/load-state.ts:8`），守卫 `list-counters.spec.ts` |
| 引用列表 / 选择器 / 面板 | 九处补独立 `xxxError` + 可见错误态 + 重试；守卫 `silent-clear-empty-states.spec.ts` |

**模板的规范顺序（必须照抄）**：

```
有数据 → 失败 → 加载中 → 空态
```

- **失败态排在加载态之前**（失败信息更具体）；**空态只在「成功且确实为空」时出现** —— 空态文案是对数据的断言，只能来自一次成功的读。
- 参考实现：`src/views/next/NextOverviewView.vue:560-588`（`:560` `v-if="feed.length"` → `:571` `v-else-if="feedError"` → `:585` `v-else-if="feedLoading"` → `:588` `v-else` 空态）。
- **表格场景不要手写这套链**，直接用 `UiTable` 的四件套（`frontend/src/ui/Table.vue`）：`:error`（`:59`，非空即「加载失败 + 原因 + 重试」取代空态；默认值 `:71`）、`:loading`（骨架行）、`empty-title` / `empty-description`、`@retry`（`:79` emit，渲染在 `:220-238`，带 `data-testid="table-load-failed"` / `table-load-retry`，图标用 `--ui-danger-bg` / `--ui-danger-fg`）。范例 `NextPlansView.vue:512-521`；**采用面**：`views/next` 下 **31 个文件**传 `:error=`、**30 个文件**传 `@retry=`。
- ⚠️ `UiTable` 的失败态**刻意不复用** `UiEmptyState`（`src/ui/EmptyState.vue`，props `title` / `description` / `compact` + 默认 slot 放行动按钮）：失败块与 `empty` slot 是 `v-if` / `v-else` **互斥**的两个分支（`Table.vue:239` 起才是 `v-else`），这样「失败」在结构上不可能被画成「空」。`UiEmptyState` 仍由页面直接使用（`NextKeysView.vue:1102,1116`、`NextSkillsView.vue:176` 等）。
- 趋势图有对应的 `emptyText` prop（`src/ui/TrendChart.vue:45`，默认 `'暂无趋势数据'` `:54`，渲染于 `:190`）。

#### 四条实现纪律

1. 每个异步引用列表都要有**独立的** `loading` + `error` ref，**不要复用保存/校验错误槽**（`NextAdminSkillsView.accessError` 是保存槽，加载错误另用 `refsError`）。
2. 空态文案一律放进 `v-else`，门控是「成功且确实为空」。
3. 加载失败要在**面板自身**显示并可重试；面板失败**不牵连**页面级 `loadError`（`loadFeed` 刻意不 throw，保持 #1138 的隔离）。**失败隔离与失败可见是两条同时成立的契约。**
4. 失败态要排在加载态**之前**判定，别被 `quotaLoading` 之类的 loading 盖住；**错误信息只在读到结果之后更新（成功才清）**。

#### 两条反例教训（照抄会重犯）

1. **清掉错误 ≠ 已读到空数据**。重试时清空 `error` 而数据仍为空 → 空态文案**原样回归**（请求挂起则一直显示），而且**能穿过按名字判定的守卫**（`!feedError` 被当成门控）。修法：补一个 `loading` ref 并把它排进链里。
2. **重试在途清掉错误条 = 制造静默窗口**。错误块随 `v-if` 卸载后只剩空下拉，连「重试」按钮本身也一起消失、无法显示 loading。修法：错误只在成功后才清，重试在途按钮进 `:loading`。

#### 配套守卫：`src/__tests__/silent-clear-empty-states.spec.ts`（530 行，3 条规则）

| 规则 | 扫什么 | 要求 | 豁免 |
|---|---|---|---|
| 1 | 模板里所有可渲染的 `暂无 / 还没有 / 没有更多` 文案 | 必须落在允许失败/未加载的门控下（自身表达式、自身 `v-if` 链、任一祖先、祖先的 `:error` 绑定） | `TEXT_EXEMPT` **16 条**，理由两类：「失败信号在同弹窗/同面板别处可见」或「#657 既定决定」 |
| 2 | `catch` 里 `X.value = []` 或整条回答是 `.catch(() => [])` | 处理器体内必须留下**可见失败信号**（`toast.error(` / 赋给 `*Error` / `*Failed*` ref / `setError(` / `throw`） | `CLEAR_EXEMPT` **7 条**，全属 fail-open 或 #657 降级语义 |
| 3 | `try` 块里 `await api.*` 而**没有 `catch`** | 出现即违规 | **刻意不设豁免表**：「要么补 catch，要么该读取属于自持错误语义的层」（`auth.fetchMe` 永不 reject，故 `NextUnavailableView` 的 `try/finally` 不算违规） |

**防腐 / 防空转设计（新增守卫请照抄这个模板）**：每条豁免要求理由长度 > 10、片段必须匹配到 ≥1 个命中、且 ≥1 个命中仍未门控 —— 豁免不再需要时守卫**会红**并提示删除；规则 1 `files >= 30` / `sites >= 40`、规则 2 `handlers >= 8`、规则 3 `tryBlocks >= 120`，防「提取逻辑坏掉之后守卫永远绿」。

> 一条 CI 事故值得记：`scriptOf()` 的 SFC `<script>` 提取正则被 CodeQL `js/bad-tag-filter` 报 high 告警（「不匹配大写 `<SCRIPT>`」）。**只加 `i` 不够** —— 该查询取「最短命中」，修掉大写案后会落到闭合标签案。最终收敛为 `/<\/?script[^>]*>/i`，且闭合标签允许空白/属性。

### 12.2 铁律：被路由渲染的页面组件必须恰好一个元素根

**违反它的后果是静默且灾难性的**。外壳出口是 `components/NewShell.vue:907` 的 `<Transition name="shell-page" mode="out-in">`。页面模板若有多个顶层节点，组件就渲染 Fragment 根：

1. `renderComponentRoot` 对非元素根告警，但 `setTransitionHooks` **仍把 hooks 递归转移到 fragment vnode**（Vue 3.5.40 `runtime-core:1657-1667`）；
2. `out-in` 分支置 `state.isLeaving = true`，**只由 `leavingHooks.afterLeave` 清除**（`runtime-core:1415-1425`）；
3. renderer 的 `remove(fragmentVNode)` 走 `removeFragment`（`runtime-core:6783-6794`），**从不调用 `transition.afterLeave()`**。

→ `isLeaving` 永久为 true，此后每次渲染 `return emptyPlaceholder(child)`（`runtime-core:1388`）。**结果：从该页离开后出口永久 `<!---->`，无任何报错、错误边界不接管，直到整页刷新。**

**正确做法**：需要多个顶层弹层时，把它们**嵌进页面根 `div` 内部** —— `UiDrawer` / `UiDialog` 本身都 `Teleport` 到 body（`ui/Drawer.vue:184`；`ui/Dialog.vue` 注释 `:4`），所以占位只是锚点，**DOM / 视觉 / 交互不变**；`v-else` / `v-else-if` 分支归并到前一根，算单根。

**守卫**：`src/__tests__/transition-chain-single-root.spec.ts`（153 行）静态提取路由表里的 **38 个**页面组件（`ROUTE_COMPONENT :40`），逐一检查顶层**恰好一个元素根**（注释 / 空白不计），失败输出**点名文件 + 行号**。**范围刻意收窄**：只查路由表里的组件 —— 过渡链之外多根无害，`App.vue` 就是两个根（`App.vue:15,18`），它因「不在路由表」而豁免（#807 教训：更严但无意义的检查会被无视）。豁免表**当前为空**，且第二条测试会对「已不再需要」的豁免报红 —— **不要轻易加条目**，整棵路由树离一次 `router.ts` 编辑只有一步。

**配套 e2e**：`e2e/mcp-page-navigation.spec.ts`（见 §9.2）。

### 12.3 异步动作的纪律

异步代码最容易踩的三类坑：轮询停机 / 在途重复提交 / 面板读取串行或致命。以下每条都是硬性要求：

1. **轮询失败 ≠ 终态**：`catch` 里绝不能无条件 `clearInterval` —— 一次瞬时失败（代理 502、服务重启、笔记本休眠）会让行冻结在一个已经错误的状态，无提示、只能手动刷新。改为**有界重试**：`MAX_POLL_ERRORS = 5`（间隔 2s ≈ 10s），**停机必须 toast 明确告知**（`'状态查询连续失败，已停止自动刷新，请刷新页面查看最新状态。'`），成功一次要**清零**计数器；计数器是 **per-poll 闭包变量**，不是组件级共享。范例：`NextAdminExportsView.vue:164-197`、`NextAdminReconciliationsView.vue:371-410`。
2. **`catch` 里第一件事是查 `pollTimers.has(timer)`** —— 区分「组件已卸载」（静默退出、**零 UI 副作用**）与「真实失败」。卸载语义不能被失败处理污染。
3. **非幂等写操作要有在途守卫**：入口守卫 `await` 前**同步**置位、`finally` 复位，并接上 `UiButton` 的 `:loading`（它的 `disabledState` 落到原生按钮，不只是转圈）。库上的唯一索引不一定拦得住（`plan_seats` 的索引带 `WHERE external_seat_ref IS NOT NULL`，而表单只下发 `displayName` / `assignedUserId` —— 双击即两次写库）。
4. **同波并行 + 失败隔离可以兼得**：面板的附加读取要「**先启动、后在面板自己的 try/catch 里 await**」。放进页面级 `Promise.all` 会让它**致命**（失败即整页空）；完全串行又白白排队。启动后若存在「可能没人 await」的路径，挂 `.catch(() => undefined)` 防 unhandled rejection。范例：`NextOverviewView.vue:430-444` + `:305-349`。
5. **同一份数据一次挂载只取一次**，把结果**作为参数传递**，而不是让子加载重新取（重复请求的渲染输出与正确实现完全相同，所以长期无人察觉）。范例：`NextOverviewView.vue:416-453`。
6. **失败路径的测试**：mock 的 rejection 必须是客户端真实会抛的类型（`ApiError` —— 页面 `catch` 只对它记录 `loadError`，用 `new Error(...)` 会造出**没有可咬之物的真空断言**）；断言的载体（`text` vs `title` **属性**）必须与模板真实渲染位置一致。**调用次数本身就是断言**（渲染输出两种实现一样时，只能靠 `toHaveBeenCalledTimes(1)` 抓住重复请求）。

### 12.4 源码守卫（source guards）的共同设计

本仓最有辨识度的工程实践：把「模板 / 样式纪律」钉成**不挂载、直接读源码做正则与结构审计**的单测（清单见 §9.1 的「静态源码审计」组）。新增守卫时照抄这三件套：

1. **防空转阈值** —— 声明「至少应扫到 N 个文件 / 站点 / 处理器 / try 块」，防「提取逻辑坏掉之后守卫永远绿」。
2. **带理由的豁免表** —— 每条豁免必须写明为什么安全。
3. **防腐测试** —— 豁免条目匹配不到、或已不再需要时，**守卫自己变红**并提示删除。
