## 这个目录是什么

`docs/` 下的其余文档是**按主题拆分的规格**（架构 / 数据库 / API / 运维各一份）。
本目录不同：它按**接手顺序**组织，回答的是"我该怎么把这个系统跑起来、看懂、改起来"。

所以它和 `docs/` 是互补而非竞争关系：

| 你想知道 | 看哪边 |
|---|---|
| 某个契约的精确定义（字段、枚举、约束） | `docs/` 的专项契约（以 `document-map.md` 为准） |
| **这东西整体怎么运转、我该从哪读起** | 本目录 |
| 当前做到哪了、下一步做什么 | [`progress.md`](../progress.md) |

## 三条使用规矩

**1. 手册里的 `文件:行号` 是定位线索，不是精确坐标。**
它们基于页首写的基线 commit。代码一改，行号就漂。**请用类名 / 方法名 / 常量名重新搜。**
规律是"哪个文件动过哪个就失效"，没动过的文件基本 100% 准。凡是有漂移风险的行号，手册里都标了 ⚠️。

**2. 文档与代码冲突时，以代码为准。**
这不是客套——`docs/` 里有若干实测过的失真，手册各章末有专门章节列出来。

**3. 先建立全局，再按任务查。别从头读到尾。**
